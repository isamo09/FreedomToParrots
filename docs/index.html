Freedom To Parrots — проект, с помощью которого любой желающий, имея обычный ПК, телефон или ноутбук, может развернуть туннель для интернет-трафика внутри интернет-звонка, чтобы получить доступ к сайтам там, где это необходимо. Запуск занимает пару кликов и даёт медленное, но рабочее соединение при его отсутствии. Разворачивается на Windows, Linux, Android (Termux) и любых других платформах — вся программа (панель управления и ядро туннеля) собрана в один исполняемый файл под каждую из них.

КороткоБыстрый старт

Полная версия — в разделах установки ниже, здесь — общая идея в шести шагах.

  1. Выберите, где будет сервер, к которому подключаются клиенты — это может быть любой ПК, ноутбук или даже телефон — и скачайте под него совместимую сборку из последнего релиза.
  2. Создайте для программы отдельную папку и переместите скачанный файл туда — не запускайте его прямо из «Загрузок»: рядом с ним появятся настройки, ключи и логи, и удобнее, когда это всё в одном отдельном месте, например:
    mkdir FreedomToParrots && cd FreedomToParrots
  3. Запустите его из этой папки и откройте панель управления по адресу из консоли, войдя по отображённому там паролю.
  4. В панели нажмите «Добавить устройство», указав ссылку на активный звонок — например, на Яндекс Телемосте.
  5. Получите QR-код или ключ для настройки подключения этого устройства.
  6. Для подключения скачайте клиент olcBOX (ссылки в разделе «Клиент» ниже) и добавьте в него полученную конфигурацию.
Для устойчивой работы рекомендуется выйти из самого звонка в клиенте-звонилке, не завершая его — интернет-туннель при этом продолжит работать.
Серверу нужен стабильный выход в интернет — обычного домашнего Wi-Fi роутера достаточно — и он должен быть включён и запущен всё то время, пока к нему должны подключаться клиенты. Выключили компьютер с сервером или он ушёл в спящий режим — подключение работать не будет, пока его не запустят заново.

СерверWindows

Один .exe, ничего не устанавливается.

⭳ FreedomToParrots-windows-amd64.exe

  1. Скачайте файл по ссылке выше (это всегда сборка из последнего релиза).
  2. Создайте для программы отдельную папку — не запускайте её прямо из «Загрузок» — и переместите скачанный .exe в неё. Через проводник: правой кнопкой → «Создать» → «Папку»; в PowerShell то же самое одной командой:
    mkdir FreedomToParrots; cd FreedomToParrots
    затем переместите exe в открывшуюся папку.
  3. Запустите файл двойным кликом именно из этой папки — рядом с ним появятся настройки, ключи и логи. Откроется отдельное окно консоли с иконкой и названием Freedom To Parrots. Windows SmartScreen может предупредить про «неизвестного издателя»: это ожидаемо для нового публичного релиза без платной подписи — «Подробнее → Выполнить в любом случае».
  4. В консоли появится адрес панели (кликабельный) и пароль, сгенерированный при первом запуске.
  5. Откройте адрес в браузере на этом же компьютере (или с телефона в той же сети — тогда подойдёт адрес вида http://192.168.x.x:8858/), войдите по паролю.
Крестик на окне не закрывает программу сразу. Первый клик покажет предупреждение и ничего не остановит, второй клик (в течение нескольких секунд) — закроет и корректно остановит все туннели. Чтобы просто оставить работать в фоне — сверните окно вместо закрытия, или используйте Планировщик заданий Windows для запуска при входе.

СерверLinux

Статический бинарник, без зависимостей — подходит для любого дистрибутива и для VPS.

⭳ FreedomToParrots-linux-amd64 ⭳ FreedomToParrots-linux-arm64

  1. Создайте отдельную папку для программы и перейдите в неё — не запускайте бинарник прямо из ~/Downloads, рядом с ним появятся настройки, ключи и логи:
    mkdir FreedomToParrots && cd FreedomToParrots
  2. Скачайте в неё бинарник под вашу архитектуру: amd64 — обычный сервер/ПК, arm64 — ARM-сервер, Raspberry Pi.
  3. Сделайте исполняемым и запустите из этой же папки:
    chmod +x FreedomToParrots-linux-amd64
    ./FreedomToParrots-linux-amd64
  4. Адрес панели и пароль будут выведены прямо в терминал.
  5. Чтобы панель продолжала работать после закрытия терминала — запустите её в tmux/screen, или через systemd (юнит с ExecStart=/путь/до/FreedomToParrots-linux-amd64).

СерверmacOS

Отдельные сборки под Intel и Apple Silicon.

⭳ FreedomToParrots-darwin-arm64 (M1/M2/M3/M4) ⭳ FreedomToParrots-darwin-amd64 (Intel)

  1. Создайте отдельную папку для программы и переместите туда скачанный файл — не запускайте его прямо из «Загрузок»:
    mkdir FreedomToParrots && cd FreedomToParrots
  2. В Терминале, из этой папки: chmod +x FreedomToParrots-darwin-arm64 && ./FreedomToParrots-darwin-arm64
  3. Gatekeeper спросит про неподписанный бинарник — разрешите запуск через «Системные настройки → Конфиденциальность и безопасность → Всё равно открыть».
  4. Адрес и пароль панели появятся в Терминале.

Сервер · экспериментальноAndroid / Termux

Termux — это обычный aarch64 Linux userland, поэтому туда идёт FreedomToParrots-linux-arm64.

⭳ FreedomToParrots-linux-arm64

  1. Установите Termux (из F-Droid — версия из Google Play устарела и не обновляется).
  2. Создайте отдельную папку и перейдите в неё, затем скачайте бинарник прямо в Termux:
    mkdir FreedomToParrots && cd FreedomToParrots
    curl -LO https://github.com/isamo09/FreedomToParrots/releases/latest/download/FreedomToParrots-linux-arm64
  3. chmod +x FreedomToParrots-linux-arm64 && ./FreedomToParrots-linux-arm64
Известное ограничение: на Android 11+ (API 30+) без root SELinux запрещает домену untrusted_app, в котором работает Termux, читать список сетевых интерфейсов через netlink — из-за этого сбор ICE-кандидатов может не пройти. На Android ≤10 или на рутованном Termux ограничения нет. Если сервер поднимаете не на телефоне, а телефон нужен только как клиент, подключающийся к панели через браузер — это ограничение вас не касается.

СерверFreeBSD, OpenBSD и другие

Ядро туннеля собирается для FreeBSD и OpenBSD (amd64/arm64) без cgo, так что релиз включает и их. Запуск — так же, как на Linux: отдельная папка (mkdir FreedomToParrots && cd FreedomToParrots), в неё — скачанный бинарник, сделать исполняемым и запустить из терминала.

⭳ freebsd-amd64 ⭳ freebsd-arm64 ⭳ openbsd-amd64 ⭳ openbsd-arm64

Нужна сборка под ОС, которой нет в списке? Ядро туннеля и эта панель — чистый Go без cgo, кросс-компиляция на любую поддерживаемую Go платформу — вопрос правки матрицы в .github/workflows/release.yml. Заводите issue в репозитории.

КлиентПодключение устройства — olcBOX

В панели каждое добавленное устройство получает свой QR-код и строку подключения вида olcrtc://provider?transport@room#key$name. Разобрать их умеет готовое GUI-приложение olcBOX — сторонний мультиплатформенный клиент olcrtc (не часть этого репозитория, но его сборки лежат в том же релизе для удобства).

⭳ Android (.apk, universal) ⭳ Windows (portable .zip) ⭳ macOS Apple Silicon (.dmg) ⭳ macOS Intel (.dmg) ⭳ Linux (.AppImage) ⭳ iOS (.ipa, неподписанный)

  1. Установите файл под свою платформу (Android/Windows/AppImage запускаются сразу; iOS требует подписи/sideload, macOS — снять карантин Gatekeeper, как и для самой панели).
  2. В панели откройте карточку устройства → «Ключ и QR» и отсканируйте QR прямо в olcBOX, либо скопируйте строку подключения и вставьте её в приложение вручную.
Контрольные суммы: файлы olcBOX сопровождает SHA256SUMS.txt из релиза апстрима — сверьте перед установкой, если это важно для вашей модели угроз. Исходники и другие варианты сборки (arm64/armeabi APK, exe/msi для Windows): alananisimov/olcbox.
Без стороннего приложения, вручную: тот же исполняемый файл Freedom To Parrots содержит то же самое ядро туннеля, которое умеет работать и клиентом (режим cnc) — получившийся туннель поднимает локальный SOCKS5-прокси. Формат конфигурации и разбор строки подключения описаны в документации ядра (uri.md).

Частые вопросы

Где взять пароль от панели?

Он генерируется случайно при самом первом запуске и всегда выводится в консоли, из которой запущена программа — прокрутите её вывод вверх, если пропустили. Изменить пароль можно, отредактировав data/settings.json рядом с исполняемым файлом, и перезапустив программу.

Это обходит белые списки?

Зависит от выбранного сервиса-провайдера видеозвонков, а не является гарантированным свойством самого инструмента. olcrtc не открывает доступ «из ниоткуда» — он прячет TCP-трафик внутри настоящего WebRTC-соединения с одним из поддерживаемых провайдеров (Jitsi, Яндекс Телемост, WbStream). Если сеть ограничивает доступ именно белым списком разрешённых адресов и нужного провайдера в этом списке нет — само видеосоединение с ним не установится, и туннель внутри него тоже не поднимется. Если же провайдер в сети разрешён (например, домены Jitsi/Телемоста/WbStream не заблокированы), туннель внутри такого разрешённого соединения работает. Так что практический смысл есть в первую очередь там, где ограничивают по спискам домен-в-домен или по типу трафика, а не там, где сами эти видеосервисы тоже недоступны.

Насколько это безопасно и на чём вообще держится?

Принцип olcrtc: вместо обычного TCP-соединения к нужному сайту устанавливается настоящее зашифрованное WebRTC-соединение с одним из провайдеров видеозвонков, и внутри него — поверх видео-, аудио- или дата-канала — передаётся туннелируемый трафик, дополнительно зашифрованный собственным ключом каждого устройства. Со стороны сети это выглядит как обычный видеозвонок к обычному публичному сервису. Но это не независимая гарантия: вся схема держится на милости конкретного провайдера (веб-платформы) — если Jitsi, Яндекс Телемост или WbStream начнут детектировать и блокировать такой паттерн трафика, изменят протокол или закроют используемые режимы (как WbStream уже ограничивает часть транспортов для обычных гостей звонка), туннель через них перестанет работать без какого-либо предупреждения — это внешний фактор, никак не контролируемый ни ядром olcrtc, ни этой панелью.

Почему пишет «недоступно» про трафик?

Точный подсчёт переданных байт использует системные счётчики процесса. Надёжно это работает только на Linux (/proc/<pid>/io). На Windows похожий API (GetProcessIoCounters) технически есть, но на практике он отражает файловый ввод-вывод, а не сетевой — трафик реальных WebRTC-звонков через него не рос вообще. Показывать заведомо неверное застывшее число хуже, чем честно писать «недоступно» — поэтому на Windows и macOS/BSD именно так. Сами сессии при этом работают полностью, просто лимит трафика на этих ОС выставить нельзя.

Больше 5 устройств — это правда проблема?

Не запрет, а предупреждение: каждое устройство — это отдельный замаскированный видеозвонок, и много одновременных звонков с одного адреса начинают заметно нагружать канал и делать поведение более отличимым от обычного пользователя. Панель покажет предупреждение, но не остановит сессии сама.

Ссылка на звонок «протухла» — что делать?

Провайдеры звонков (Телемост, WbStream) не гарантируют вечную жизнь комнаты. Если панель показывает предупреждение о недоступности для устройства, которое раньше подключалось, создайте новую комнату у провайдера и обновите Room ID через «Изменить» в карточке устройства — ключ шифрования и настройки транспорта при этом сохранятся.

Как обновиться до новой версии?

Программа сама проверяет GitHub Releases при запуске и потом раз в 12 часов. Если есть версия новее — появится баннер и в консоли, и в панели. Ничего не ставится автоматически без подтверждения: нажмите «Обновить и перезапустить» в панели (или наберите u и Enter в консоли). Перед установкой скачанный файл сверяется по SHA256 с суммой из релиза.

Может ли аккаунт в сервисе звонков пострадать от такого использования?

Формально это использование сервиса не по прямому назначению, поэтому исключать ограничение или блокировку аккаунта за чрезмерную активность нельзя — это риск того, кто принимает решение так делать. На момент публикации авторам о подтверждённых случаях блокировок за это неизвестно, но это не гарантия на будущее.
